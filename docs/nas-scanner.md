# NAS 音乐自动扫描规则

扫描器把 NAS 文件转换成结构化音乐资料库。iOS App 不读取目录树，也不显示文件名、扩展名或 NAS 路径。

## 扫描范围

只扫描配置中的音乐根目录，例如：

```text
/music/library/
  专辑名称/
    cover.jpg
    01 - 歌曲名称.flac
    01 - 歌曲名称.lrc
```

NAS 的照片、下载、备份和私人目录不会被扫描。当前支持扫描 AAC、AC3/EAC3、AIFF、ALAC、AMR、APE、CAF、DSD（DFF/DSF）、DTS、FLAC、M4A/M4B、MKA、MP2/MP3/MP4、MPC、OGG/OGA、Opus、Shorten、TAK、TTA、WAV、WMA 与 WavPack。

其中 AAC、AIFF、ALAC（M4A 容器）、CAF、FLAC、M4A/M4B、MP3/MP4 和 WAV 直接提供原文件；APE、WavPack、TTA 等无损来源在扫描阶段无损缓存为 FLAC；DSD 转为最高 192 kHz PCM/FLAC；OGG、Opus、WMA、MPC 等非原生来源缓存为 256 kbps M4A。扫描器会同时检查容器和音频编码，例如 M4A 中的非原生编码仍会转码。转码失败只影响该曲目，并记录为扫描错误，不会阻塞其余资料库。

## 资料解析优先级

歌曲标题、艺人、专辑、曲序和发行时间：

1. 音频文件内嵌标签。
2. 专辑目录中的 `metadata.json`。
3. 专辑目录名和规范化文件名。

封面：内嵌封面优先，其次为同目录下的 `cover.webp`、`cover.jpg` 或 `folder.jpg`，最后使用 App 的品牌占位图。

歌词：内嵌同步歌词优先，其次为与歌曲同名的 `.lrc`，再其次为 `.txt` 纯文本歌词。

可选 `metadata.json` 示例；内嵌音频标签优先级更高：

```json
{
  "album": "专辑名称",
  "albumArtist": "你的艺名",
  "releaseDate": "2026-06-22",
  "tracks": {
    "01 - 歌曲名称.mp3": {
      "title": "歌曲名称",
      "track": 1
    }
  }
}
```

## 自动发布规则

- 文件大小连续 30 秒不变后才开始处理，避免扫描到尚未传完的文件。
- 音频能完整探测、转码产物验证成功后，立即写入新目录版本。
- 同一专辑名和专辑艺人的歌曲自动组成专辑，按碟号和曲序排列。
- 单曲可以归入“单曲与 EP”，不会以零散文件形式展示。
- 内容哈希相同的文件视为重复项，不重复显示。
- 文件修改后重新转码并替换歌曲版本；删除文件后从下一版目录中移除。
- 一次扫描的目录更新必须是原子的，不能让 App 看到只生成了一半的专辑。

## App 中的呈现

扫描结果形成音乐资料库，而不是一个巨大的播放列表：

- 首页：艺人信息、精选发行、最新专辑。
- 专辑页：封面、发行信息和按曲序排列的歌曲。
- 正在播放：大封面、歌词、进度和播放队列。
- 设置：服务器状态、版本与播放能力，继续保留为独立页面。

歌单是资料库之上的独立功能。后续可以增加“热门歌曲”“创作精选”等策划歌单，但 NAS 文件夹本身不直接等同于歌单。

## 扫描时机

- 文件系统事件触发增量扫描。
- 服务启动时执行一次一致性扫描。
- 每 6 小时执行一次完整校验，修复遗漏的文件系统事件。
- 扫描成功后刷新目录缓存；音乐页打开时每 60 秒检查一次，App 回到前台时也会检查更新。
