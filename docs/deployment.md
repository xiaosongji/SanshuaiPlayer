# NAS 与公网部署方案

## 推荐拓扑

```text
NAS 音乐目录 -> 自动扫描/转码 -> 音乐目录数据库
                         -> 对象存储/CDN 播放副本

iOS App -> api.your-domain.com -> 音乐 API
        -> media.your-domain.com -> 签名音频与封面
```

NAS 保存 WAV/FLAC 母带、原始封面、歌词和备份。面向用户的 AAC/M4A 或 HLS 文件发布到对象存储/CDN，避免家庭上行带宽、断电和 NAS 维护影响播放。

## 不允许的部署方式

- 不把 SMB、WebDAV 或 NAS 管理端口开放到公网。
- 不在 App 内保存 NAS 管理员账号、固定媒体密码或永久 API 密钥。
- 不把本地路径或内网 IP 返回给 App。
- 不允许客户端提交任意媒体 URL 给服务器代取。

## 自动扫描与发布流水线

1. 新歌曲写入指定的 NAS 音乐目录，文件稳定后触发扫描。
2. 读取音频标签、专辑、曲序、封面和同名歌词文件。
3. 校验文件哈希、采样率、声道和可解码性，重复文件只保留一条目录记录。
4. 使用 FFmpeg 生成 AAC/M4A 正式播放版本；网络条件跨度大时增加 HLS 多码率版本。
5. 上传播放副本并验证可以读取、拖动进度和完整播放。
6. 原子更新音乐目录；成功的歌曲自动出现在 App，整个流程不需要人工审核。

损坏、未写完或无法解码的文件不会影响现有目录。扫描器会把错误写入日志并继续处理其他歌曲；文件修复后自动重试。

## 若必须由 NAS 直接提供音频

使用独立反向代理或云端入口，只向代理开放只读媒体目录。公网仅开放 `443`，配置 TLS、Range、限流、防盗链、访问日志和自动封禁。家庭网络处于运营商 CGNAT 时，需要云服务器反向通道或安全隧道，不能依赖路由器端口映射。

这种模式仍受家庭上传带宽、断电和设备维护影响，不建议用于公开发行。

对于没有公网 IP 的 fnOS，使用出站隧道连接独立音乐子域名。隧道只连接音乐容器，不能指向 fnOS 的 `5666/5667` 管理端口。面向大量公开用户时，NAS 应作为母带和扫描源，播放副本仍应同步到对象存储/CDN。

## 上线检查

- 域名、HTTPS 证书和续期监控
- API、数据库、队列和对象存储健康监控
- NAS 母带至少一份异地备份
- 发布、下架和回滚演练
- 管理后台独立账号、双因素认证和审计日志
- App Store 隐私说明、隐私政策和版权资料
- 若服务部署在中国大陆，按实际云服务和业务类型完成所需备案及合规手续
